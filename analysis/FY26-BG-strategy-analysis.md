# FY26 产品市场一BG经营战略分析

## 分析视角：先看基本盘，再叠加创新

---

## 一、基本盘：卖什么 × 怎么卖

### 1.1 核心产品矩阵

按文档中各PBU（产品业务单元）和客户需求反推，主力产品分为**五大板块**：

| 板块 | 核心产品 | 典型客户场景 | 竞争对手 |
|------|---------|-------------|---------|
| **终端安全** | 天擎（含信创XC版）、零信任TAC/TAP、EDR、浏览器、企业移动管理 | 政务终端管控、信创替代、准入控制 | 深信服、安恒、天融信 |
| **安全运营** | NGSOC、AISOC、天眼、探针、蜜罐、漏扫、靶场 | 态势感知、威胁检测、安全运营中心 | 深信服、启明 |
| **边界安全** | 防火墙(NGFW)、网闸、SSLO、工控防火墙、一体机 | 网络边界防护、等保合规 | 天融信、深信服 |
| **云与数据安全** | 数管平台、椒图(主机安全)、堡垒机、API安全、密码产品、CSMP | 数据分级分类、云安全、运维审计 | 安恒、青藤 |
| **安全监管** | 监管态势平台、互联网自监管 | 网信办/公安监管、关保合规 | 启明、绿盟 |

**附加能力线**：取证产品(盘古)、威胁情报(TIP)、CAASM资产测绘

### 1.2 传统打法（去掉创新后的底层逻辑）

#### **M1 战略核心客户（高价值+高关系）→ 深度绑定，吃存量**

**打法本质**：用"人"换"钱"，驻场锁客

- **金牌PM驻场**：核心客户必须有人盯着（117人月锁定）
- **SLA兜底**：10分钟响应、1小时到场、30分钟处置——用服务承诺绑定客户
- **高层天梯拜访**：CEO/高管亲自破冰，建信任关系（文档列了60+个需要CEO拜访的客户）
- **定制开发资源倾斜**：447人月研发资源，绝大部分给M1客户
- **产品组合打包**：终端+运营+边界+数据安全全栈覆盖，提高替换成本

**实质**：这不是产品竞争力驱动，是**关系+服务+资源投入**驱动的重资产打法。

#### **M2 现金牛客户（高价值+低关系）→ 价格绞杀，抢份额**

**打法本质**：打价格战，干掉竞争对手

- **逆向竞价**：让渠道商竞价拿货，以竞对价格为锚点
- **精准定价**：防火墙按天融信65%-75%定价，终端安全按安恒下浮5%-7%
- **以旧换新**：最高抵扣20%，解决客户换代阻力
- **批量赠送**：100套以上免费1年维保
- **渠道分利**：厂商与渠道3:7分成（渠道拿大头），深度绑定渠道利益

**对每个竞对的绞杀策略**：
| 竞对 | 策略核心 |
|------|---------|
| **深信服** | 价格锚定70%、用AI+零信任降维打击传统防火墙、低成本SaaS/一体机打下沉市场 |
| **天融信** | 防火墙65%-75%定价、终端组合折扣、以旧换新补贴 |
| **安恒** | 终端低价5%-7%抢占、订阅模式差异化 |
| **360/数默/微步** | 差异化竞争，主打企业级SaaS/私有化/性价比 |

**实质**：纯粹的**价格战+渠道战**，核心武器是成本控制和渠道覆盖。

#### **M3 潜力客户（低价值+高关系）→ 制造焦虑，撬预算**

**打法本质**：免费渗透测试 → 出报告 → 给安全部门"递刀子"找领导要钱

- **AI渗透测试义诊**：低成本/免费检测，出红头文件级隐患报告
- **话术**：「不整改即面临合规处罚/业务停摆」
- **轻量体验**：安全运营周卡/月卡、1-3个月免费试用
- **以旧换新**：把竞对设备折价换购自家产品

**实质**：**恐惧营销+免费试用**的经典SaaS获客套路，只不过放在安全行业语境下。

#### **M4 长尾客户（低价值+低关系）→ 渠道自动化收割**

**打法本质**：不投入人力，让渠道自己卖

- **标准化产品**：免费自助诊断工具引流
- **渠道在线下单**：D级散户完全自助
- **原厂不投入**：只提供工具和标准化方案

**实质**：**渠道分销的标准化生意**，走量不走质。

### 1.3 传统打法的三条主线

总结下来，去掉所有"创新"包装，文档的核心打法就三条：

```
主线一：M1靠关系和服务（重资产投入换锁定）
主线二：M2靠价格战（绞杀竞对抢份额）
主线三：M3/M4靠恐惧营销+渠道（低成本获客，向上转化）
```

全集团的增长逻辑是：**M3→M1（深挖潜力）+ M2→M1（夺权转化）= 填补5600万业绩缺口**。

## 二、创新层：叠加在基本盘上的新模式

### 2.1 创新模式清单

| 创新模式 | 具体内容 | 适用场景 | 本质 |
|---------|---------|---------|------|
| **账号租赁** | 平台建好后向下属单位租账号收费 | 军工(航天科工)、宁夏网信办 | 从卖设备变SaaS化收费 |
| **联合运营** | "信任+技术"联营，嵌入客户业务流程长期分润 | 华东空管、司法部 | 从项目制变运营分成 |
| **监管即服务** | 监管单位建平台 → 推动被监管单位采购 → 被监管单位付费 | 青海公安/网信、宁夏 | 用监管权力驱动销售 |
| **AI订阅包** | 信创+攻防+检测+AI能力三档订阅 | 电网、央企 | 从一次性采购变持续订阅 |
| **效果付费** | 按告警处置效率/误报率下降付费 | 广州供电局 | 从卖产品变卖效果 |
| **联合实验室/IP共创** | 与客户共建实验室，联合申报标准 | 中煤、南网科研院 | 用研发合作锁定客户 |
| **供应链嵌入** | AISOC供应链模块嵌入客户上下游供应商 | 能源、政府 | 从单点覆盖变生态覆盖 |
| **总集身份** | 作为"安全总集"把控客户信息化审批 | 上海杨浦区 | 抢占决策入口 |
| **OEM贴牌/出海** | 授权央企贴牌出海 | 央企国际化 | 借船出海 |
| **先用后付** | 天翼云产品先试用后下单 | 新疆 | SaaS试用转化 |

### 2.2 创新模式的真正价值排序

按**商业模式变革深度**排序：

**第一梯队（真正改变收入结构）**：
1. **账号租赁 + AI订阅包** — 从一次性买断→持续ARR，这是最有价值的转型
2. **效果付费** — 按效果收费意味着产品自信，能建立长期信任

**第二梯队（改变获客方式）**：
3. **监管即服务** — 用监管权力驱动采购，获客成本接近零
4. **供应链嵌入** — 一个客户带动上下游，指数级扩展
5. **总集身份** — 占住决策入口，后续产品自然落地

**第三梯队（改变合作方式，但本质不变）**：
6. **联合运营** — 本质还是卖服务，只是合同形式变了
7. **联合实验室** — 本质是用研发投入换客户锁定
8. **先用后付/OEM** — 战术层面优化，不改变根本

## 三、关键问题与洞见

### 3.1 文档的结构性问题

**问题一：创新模式散落在各BU中，缺乏统一框架**
- 账号租赁在41军团提了，宁夏也提了，但没有统一的产品化设计
- "监管即服务"在青海提了，其他区域能不能复制？没说清楚
- 每个BU都在各自讲"创新"，但集团层面没有一个"创新模式产品化路线图"

**问题二：传统打法和创新打法混在一起，看不清主次**
- M1策略里同时写了驻场SLA（传统）和联合运营（创新），读者无法判断哪个是主力
- M2策略里价格战（传统）和订阅模式（创新）并列，但执行优先级不清

**问题三：增长逻辑依赖客户矩阵迁移，但迁移动力不足**
- M3→M1转化靠"制造焦虑"，但焦虑的持续性存疑
- M2→M1转化靠"夺权"（从竞对手里抢），但价格战的利润空间有限
- 缺乏一个**产品驱动**的增长引擎——当前全靠人和关系

### 3.2 三个关键洞见

**洞见一：这份文档的本质是"军事化销售手册"，不是"战略规划"**

它非常详细地告诉每个BU"打谁、怎么打、用什么武器"，但缺少战略层面的回答：
- 为什么客户应该选我们而不是竞对？（除了价格和关系）
- 3年后我们的竞争壁垒是什么？
- AI如何改变安全行业的竞争格局？

**洞见二：AI能力是文档最大的"口号与现实"落差**

文档反复提到AISOC、AI渗透测试、AI检测，但产品研发需求部分暴露了现实：
- AISOC需要解耦QGPT，支持对接客户已有算力（DeepSeek等）— **说明捆绑策略已被客户拒绝**
- 产品里的AI还停留在"加个接口"阶段，不是核心竞争力
- 组织AI能力现状：60%的人"抗拒AI"或"几乎不用AI"

**洞见三：信创替代是当前最大的确定性红利，但窗口有限**

文档中几乎每个BU都在吃"信创替代"的红利：
- XC天擎（国产化终端）替换Windows版
- 国产数据库适配（达梦、人大金仓）
- 全栈国产化资质要求
- 这个红利有窗口期，2-3年内会被充分消化，之后必须靠产品力

## 四、建议的文档重构方式

如果你要优化这份文档，建议按以下结构：

```
第一层：基本盘（不变的底座）
├── 我们卖什么（五大产品板块 × 典型方案组合）
├── 卖给谁（M1/M2/M3/M4客户清单与定级标准）
├── 怎么卖（传统打法三条主线）
│   ├── M1：驻场+SLA+高层关系
│   ├── M2：价格绞杀+渠道覆盖
│   └── M3/M4：恐惧营销+标准化收割
└── 打谁（竞对绞杀策略）

第二层：创新增量（叠加在基本盘上）
├── 收入结构创新（订阅化、效果付费）
├── 获客模式创新（监管驱动、供应链嵌入）
├── 合作模式创新（联合运营、IP共创）
└── 每个创新模式的：试点区域 → 验证指标 → 推广计划

第三层：能力保障
├── 产品研发需求（按优先级排序，不是按BU罗列）
├── 交付与服务资源
├── AI能力建设路线图
└── 风险矩阵
```

这样读者可以先建立基本盘的完整认知，再看创新如何叠加增量，最后看保障措施。比当前"每个BU各说各话"的结构清晰得多。
